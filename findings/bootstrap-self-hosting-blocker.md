# Bootstrap Compiler Self-Hosting Blocker

**Date**: February 9, 2026
**Status**: 🚫 Critical Blocker Identified

## Problem

The self-compiled bootstrap compiler binary fails immediately with "Cannot allocate memory" when trying to compile any program.

## Investigation Summary

### What Works
- ✅ Go-compiled bootstrap compiler (`tmp/bootstrap_test`) can compile simple programs successfully
- ✅ Generated binaries execute correctly (exit code 42)
- ✅ Self-compilation succeeds (192 functions, 49KB binary generated)
- ✅ Heap register initialization (X25/X26 = 0) present in all functions of self-compiled binary

### What Fails
- ❌ Self-compiled binary crashes immediately with "Cannot allocate memory"
- ❌ Error happens before reaching entry point
- ❌ Cannot execute in lldb either

## Root Cause: Missing Builtin Implementation

The bootstrap compiler **does not have builtin codegen** for `os.ReadFile`!

### The Problem Flow

1. **Bootstrap compiler source** (bootstrap/compiler.ease line 3895):
   ```ease
   source = os.ReadFile(filename)
   ```

2. **Go compiler handling**:
   - Recognizes `os.ReadFile` as builtin (pkg/codegen/arm64/emit.go:2859)
   - Generates inline ARM64 code: open syscall + emitBumpAlloc + read loop + close
   - Result: ~50 ARM64 instructions inline

3. **Bootstrap compiler handling**:
   - Does NOT recognize `os.ReadFile` as builtin
   - No `OP_READFILE` opcode exists
   - Treats it as regular function call
   - Generates `BL <ReadFile>` (branch and link)
   - But ReadFile has no implementation! It's builtin-only.

4. **Runtime failure**:
   - Binary tries to call non-existent ReadFile function
   - Likely branches to invalid address or uninitialized code
   - macOS kills process with "Cannot allocate memory" (misleading error)

## Comparison: Heap Allocation

**heap_alloc works** because both compilers handle it:

| Feature | Go Compiler | Bootstrap Compiler |
|---------|-------------|-------------------|
| heap_alloc | `ir.OpHeapAlloc` → `emitBumpAlloc` | `OP_HEAP_ALLOC()` → direct mmap |
| os.ReadFile | `ir.OpReadFile` → `emitReadFile` | ❌ **NOT IMPLEMENTED** |

## Evidence

```bash
# Bootstrap compiler has heap_alloc opcode
$ grep "OP_HEAP_ALLOC" bootstrap/compiler.ease
fn OP_HEAP_ALLOC() -> int { return 32 }
if instr.op == OP_HEAP_ALLOC() {  # Codegen exists

# But no ReadFile opcode
$ grep "OP_READFILE\|OpReadFile" bootstrap/compiler.ease
# (no results)

# Only usage, no implementation
$ grep "ReadFile" bootstrap/compiler.ease
source = os.ReadFile(filename)  # Line 3895 - tries to call it
```

## Solution Path

To achieve self-hosting, the bootstrap compiler must implement `OP_READFILE`:

### Step 1: Add Opcode
```ease
fn OP_READFILE() -> int { return 35 }  // Or next available number
```

### Step 2: Recognize os.ReadFile Calls
In IR generation, detect calls to `os.ReadFile` and emit `OP_READFILE` instead of `OP_CALL`.

### Step 3: Implement Codegen
Generate ARM64 code for file reading (lines 3000-3200 in compiler.ease):
```ease
if instr.op == OP_READFILE() {
    // path_reg = instr.arg1
    // dest_reg = instr.dest

    // 1. open(path, O_RDONLY, 0)
    //    X0 = path
    //    X1 = 0 (O_RDONLY)
    //    X2 = 0 (mode unused)
    //    X16 = 0x2000005 (open syscall)
    //    SVC #0x80
    //    Save fd in X20

    // 2. Allocate 1MB buffer via mmap
    //    (use existing OP_HEAP_ALLOC logic)

    // 3. Read loop:
    //    read(fd, buf+offset, remaining)
    //    X0 = fd
    //    X1 = buf + bytes_read
    //    X2 = bufsize - bytes_read
    //    X16 = 0x2000003 (read syscall)
    //    Loop until X0 <= 0

    // 4. close(fd)
    //    X0 = fd
    //    X16 = 0x2000006 (close syscall)

    // 5. Return buffer pointer in dest_reg
}
```

### Step 4: Update Pass 1
Count ARM64 instructions generated by OP_READFILE (approximately 30-40 instructions).

## Estimated Effort

- **Complexity**: Medium-High (need to handle syscalls, loops, error cases)
- **Lines of code**: ~150 lines
- **Time**: 2-3 hours
- **Risk**: Medium (syscall handling can be tricky)

## Alternative: Simpler Approach

Instead of full os.ReadFile implementation, add a **simplified version** that:
1. Always allocates 1MB buffer
2. Reads entire file in one syscall (assumes <1MB files)
3. No error handling

This would be ~50 lines and sufficient for bootstrapping.

## Lessons Learned

1. **Builtins are critical**: Can't self-host without implementing all builtins used by compiler itself
2. **Test incrementally**: Should have tested which builtins bootstrap uses before attempting full self-compile
3. **Error messages misleading**: "Cannot allocate memory" was actually "tried to call non-existent function"
4. **Heap init was red herring**: Real issue was missing builtin, not heap management
